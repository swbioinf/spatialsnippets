Getting Compute

Sarah Williams

Spatial transcriptomics analyses tend have moderate computational needs and a high degree of interactivity. They can need more ram that is available on a typical laptop or desktop computer, and the continuous need to check and evaluate results makes them ill suited to traditional HPC. A shared managed R server may be available in bioinformatics-focussed groups, but not every bioinformatician has that.

This document outlines how an individual researcher (or group) may get access to a self-managed Rstudio environment, and then set it up for real spatial transcriptomic analyses. It assumes that you have some familiarity with the linux command line and R (or, a willingness to learn).

Specifically - this is via use of the BioShell service; you can check your elegibility here

Breifly thes steps outlined are:

  1. Apply for a bishell VM
  2. Login to VM, start rstudio
  3. Decide if R version needs to be upgraded (see here), do so only if required.
  4. Install system libraries
  5. Install R packages
  6. Transfer your data across
  7. Analysis!

Getting a VM with R and Rstudio

For Australian researchers it is reccomended to apply for a ‘bioshell’ VM . These machines are built for bioinformatics workloads and come with Rstudio and JupyterLab ready to run.

See the extensive docs and how to apply here: https://sydney-informatics-hub.github.io/BioShell-User-Guide/

Alternatively, if you already have a nectar allocation for your project, you can also build your instance using the bioshell image (e.g. bioshell-v1.0.0)

These instructions assume you’ve got a newly minted bioshell machine, and have successfully logged in (see bioshell docs). They may still be helpful if your VM is from another source.

Installing R packages

Suggested system libraries

To save time, consider installing some system libraries before trying to install all your R packages.

System libraries can be fast effienct C libraries that R uses in the background to handle number crunching, file format processing, other programming languages or programs.

Installation of system libraries needs root access (sudo), which we should have on our bioshell machine. Once installed, any user may use them.

The posit website provides a command for installation of a collection of oft-used system libraries - a good place to start; https://docs.posit.co/resources/install-r.html#optional-install-system-dependencies-of-common-r-packages

Some futher installs that are helpful for spatial analyses;


# for fs package
sudo apt install libuv1-dev

# Image magcik tools
#Configuration failed to find the Magick++ library. Try installing:
sudo apt install libmagick++-dev

# Reuired for packages sf (spatial features, underlies some other packages)
#ERROR: configuration failed for package ‘sf’
sudo apt install libudunits2-dev libgdal-dev libgeos-dev libproj-dev libsqlite3-dev

# fftw (used by alabaster.sfe) via fftwtools
sudo apt install libfftw3-dev libfftw3-doc

# rJava
sudo apt install default-jre

Installing R packages

Next, you’ll want to install some R packages. Some typical examples for a new setup are listed below, - You’ll likely want more later!

Consider use of a package manager system renv, particularly if you’ll be working with multiple projects.

These’s installations will takes some time to run (by default they’ll compile from source). You might find your session stops responding or disconnects - just reconnect and run again if needed, the commands will pick up from where they left. See next section for dealing with some common errors.

Install some R packages from CRAN;

install.packages ( c(
  "BiocManager",
  'remotes',
  'tidyverse',
  'DT',
  'patchwork',
  'ggrepel'
  ) )

Install some R packages from bioconductor

Install a few things from github.

remotes::install_github("immunogenomics/presto") # Dramatic speed up of certain operations in Seurat.

Its not working! Handling R package install errors

If you get an error in install, it is often due to a dependancy of a package you need, not the package itself. It can be helpful to look for a message like ‘depencancy ’x’ was not installed’. Try to install package ‘x’ on its own - you’ll get to the error much quicker and can fix it!

Some common problems:

  • Package not available : ’ package ‘XYZ’ is not available for this version of R
    • Typo in package name
    • This is a bioconductor package, and you’re trying to install it with ‘install.packages()’. Use BiocManager()
    • This is a bioconductor package, but it is too new to be on the bioconductor release you are using (which in term is limited to your R version - see here. On your packages’s bioconductor page (example) you can see ‘in bioconductor since’ for the release version needed, (and the ‘all versions’ link for finding out what version was availble for previous bioconductor releases.
    • This package isn’t in CRAN or bioconductor - Typically you’ll install these directly from a github repo with devtools (see above)
  • Missing system library : Typically this error will offer up ‘apt install’ command or name of a system library that is needed. Sometimes it doesn’t, and you’ll need to search online for what you do need to install.
  • System library configuration issue: Some packages need further configuration before they work, consult installation instructions for those libraries (e.g. rJava)

For further infomation on R installation errors * Mastering R Through Errors and Warnings(https://bookdown.org/guokai8/mastering-r-through-errors/docs/installation-environment.html#debugging-installation-issues) Things that can go wrong when using renv

A note on R versions

When should R be upgraded?

Ideally, you won’t need to update R. The bioshell VMs come with a pre-configured R installation ready to go.

However - issues may arise when you need to use ‘bleeding edge’ bioconductor packages.

Bioconductor has a 6-monthly release cycle, and strict versioning requirements. Each bioconductor version has a minimum R requirement - and for the very latests this could be less than what is on bioshell!

If you need to work with packages (or versions of those packages) that are only available in a more recent bioconductor release than runs on your R version, then you might consider upgrading your R version.

See Bioconductor release announcements

Upgrading R

The easy way with shelley

On the command line, list the R versions that shelley knows about.

shelley find R

If the version you need is there, install it!

shelley build r

Restart your rstudio server, and see what version of R it is using. You may still need to update your system R to the freshly installed version.

The hard way - by ‘hand’

Shelley searches galaxy singularity repositories to find the latest packaged version of R. Sometimes, there are more recent versions of R in use.

Because you shoudl have full rights to these VMs, its still possible to update to a later R version in a ‘standard’ way, but its alot more work and best to have some command line and sysadmin confidence to do this.

Step 1: Install R

You’ll first need to determine your OS version, and the R version you want. It is easy to get from the posit servers. See https://docs.posit.co/resources/install-r.html

# check ubuntu version to grabe the right command (others might install fine then give librayy.so errors!)
cat /etc/os-release

export R_VERSION=4.6.1
curl -O https://cdn.posit.co/r/ubuntu-2604/pkgs/r-${R_VERSION}_1_$(dpkg --print-architecture).deb
sudo apt-get update
sudo apt-get install ./r-${R_VERSION}_1_$(dpkg --print-architecture).deb

Now we have a new version of R installed. The old version is still there.

Step 2: Switch system R to new version

# where is my default R?
# Do not have any R modules loaded
which R

# For whatever reason, all the docs seem to assume that the system R is in /usr/local/bin/, but on this server, i is in /usr/bin. 
cd /usr/bin

# Keep the old R links around just in case
sudo mv R Roldsymlink
sudo mv Rscript Rscriptoldsymlink

# Remake them, but this time to R 4.6.1
cd /usr/bin
sudo ln -s /opt/R/${R_VERSION}/bin/R R
sudo ln -s /opt/R/${R_VERSION}/bin/Rscript Rscript

Step 3: Restart Rstudio server

Stop and restart rstudio server

module load rstudio
sudo rstudio-server stop
sudo rstudio-server start

Step 4: Update Bioconductor release

After the R version update, jump back into Rstudio and update the bioconductor release to the lastest: https://bioconductor.org/install/

install.packages("BiocManager")
BiocManager::install(version = "3.23")

Getting the data there (and back again)

Perhaps the simplest way to trasnfer your data is to use SFTP via a tool like filezilla (client).

You can add a site with your server IP address, the ‘SFTP’ protocol, and your username and password, then transfer data via the graphical interface.

More information about transfering data to your bioshell machine is here: https://sydney-informatics-hub.github.io/BioShell-User-Guide/globus-howto

Happy analysis - May your data be clean and your sample sizes be adequate!
